### Q1. Explain DMA (Direct Memory Access) Controller with block diagram and working.

#### Answer

==DMA (Direct Memory Access)== is a technique in which an I/O device transfers data directly to or from main memory without continuous involvement of the CPU.

DMA is used for high-speed data transfer between memory and devices such as disk, network card, and audio/video devices.

#### Need of DMA

In programmed I/O, CPU transfers data byte by byte. This wastes CPU time. DMA solves this problem by allowing the device controller to transfer a block of data directly with memory.

#### DMA Controller Block Diagram

```text
              +----------------+
              |      CPU       |
              +----------------+
                      |
        Bus Request / Bus Grant
                      |
              +----------------+
              | DMA Controller |
              +----------------+
              | Address Reg.   |
              | Count Reg.     |
              | Control Reg.   |
              | Data Buffer    |
              +----------------+
                |            |
                |            |
        +---------------+  +-------------+
        | Main Memory   |  | I/O Device  |
        +---------------+  +-------------+
```

#### Components

| Component | Function |
|---|---|
| Address register | Stores memory address for transfer |
| Count register | Stores number of bytes/words to transfer |
| Control register | Stores read/write control information |
| Data buffer | Temporarily holds data |
| Bus request | DMA asks CPU for bus control |
| Bus grant | CPU gives bus control to DMA |

#### Working

1. CPU initializes DMA controller with starting address, count, and operation.
2. I/O device requests DMA transfer.
3. DMA sends bus request to CPU.
4. CPU completes current bus cycle and sends bus grant.
5. DMA becomes bus master.
6. Data is transferred directly between I/O device and memory.
7. Count register is decremented after each transfer.
8. Address register is incremented.
9. After transfer completion, DMA interrupts CPU.

#### DMA Transfer Modes

| Mode | Meaning |
|---|---|
| Burst mode | Entire block transferred at once |
| Cycle stealing | DMA takes one bus cycle at a time |
| Transparent mode | DMA transfers only when CPU is not using bus |

#### Who controls buses in DMA transfer?

During DMA data transfer, ==DMA controller controls the system bus== after CPU grants bus control. CPU is temporarily disconnected from bus during DMA transfer.

#### Advantages

- Faster block data transfer.
- Reduces CPU overhead.
- Useful for high-speed I/O devices.
- Improves system performance.

#### Conclusion

DMA allows direct data transfer between I/O devices and memory. It improves speed because CPU does not need to handle every byte of data.

### Q2. What are Interrupts? Explain various types of interrupts and interrupt handling mechanism.

#### Answer

==Interrupt== is a signal sent to the CPU by hardware or software to stop the current execution temporarily and service an important event.

After handling the interrupt, CPU returns to the interrupted program.

#### Need of Interrupts

- To handle I/O completion.
- To respond to errors.
- To handle urgent events.
- To avoid continuous polling by CPU.

#### Types of Interrupts

| Type | Meaning | Example |
|---|---|---|
| Hardware interrupt | Generated by external hardware | Keyboard, printer, disk |
| Software interrupt | Generated by program instruction | System call |
| Maskable interrupt | Can be disabled by CPU | Normal I/O interrupt |
| Non-maskable interrupt | Cannot be disabled | Power failure, hardware error |
| Vectored interrupt | Interrupt address is predefined | Interrupt vector table |
| Non-vectored interrupt | CPU must determine service routine address | General interrupt request |
| Internal interrupt | Generated inside CPU | Divide by zero, overflow |
| External interrupt | Generated outside CPU | I/O device request |

#### Interrupt Handling Mechanism

```text
Interrupt occurs
      |
CPU completes current instruction
      |
Save PC and processor status
      |
Identify interrupt source
      |
Jump to Interrupt Service Routine (ISR)
      |
Execute ISR
      |
Restore saved state
      |
Return to interrupted program
```

#### Interrupt Cycle

1. CPU checks for interrupt after instruction execution.
2. If interrupt is present and enabled, CPU accepts it.
3. CPU saves return address and status flags.
4. CPU branches to ISR.
5. ISR services the device/event.
6. CPU executes return from interrupt instruction.
7. Original program resumes.

#### Important Terms

| Term | Meaning |
|---|---|
| ISR | Interrupt Service Routine |
| Interrupt vector | Address of ISR |
| Interrupt priority | Order of servicing interrupts |
| Masking | Disabling selected interrupts |

#### Conclusion

Interrupts improve CPU efficiency by allowing CPU to respond to events only when needed instead of continuously checking devices.

### Q3. Differentiate between Synchronous and Asynchronous data transfer.

#### Answer

Data transfer between two units can be synchronous or asynchronous depending on whether they use a common clock.

#### Difference Table

| Basis | Synchronous Transfer | Asynchronous Transfer |
|---|---|---|
| Clock | Uses common clock | No common clock |
| Timing | Data transfer at fixed time intervals | Data transfer using control signals |
| Control signals | Less control overhead | Uses handshaking signals |
| Speed | Faster | Slower |
| Complexity | Simpler when devices have same speed | More suitable for different-speed devices |
| Flexibility | Less flexible | More flexible |
| Example | CPU-memory transfer | Keyboard/printer I/O transfer |

#### Synchronous Transfer

In synchronous transfer, sender and receiver operate using the same clock. Data is transferred at predefined time intervals.

```text
Common Clock -> Sender and Receiver transfer data together
```

#### Asynchronous Transfer

In asynchronous transfer, sender and receiver do not use a common clock. Data transfer is controlled by handshaking signals.

#### Handshaking Signals

```text
Sender: Data Valid
Receiver: Data Accepted
```

#### Conclusion

==Synchronous transfer is faster but less flexible. Asynchronous transfer is flexible and suitable for devices with different speeds.==

### Q4. Differentiate between I/O Mapped I/O and Memory Mapped I/O with examples.

#### Answer

I/O devices can be addressed using either I/O mapped I/O or memory mapped I/O.

#### Difference Table

| Basis | I/O Mapped I/O | Memory Mapped I/O |
|---|---|---|
| Address space | Separate I/O address space | Same address space as memory |
| Instructions | Special I/O instructions | Normal memory instructions |
| Address range | More memory address space available | Memory address space is reduced |
| Hardware | Requires separate I/O control signals | Uses memory control signals |
| Example instruction | `IN`, `OUT` | `LOAD`, `STORE` |
| Complexity | Slightly more control logic | Simpler programming |

#### I/O Mapped I/O

In I/O mapped I/O, I/O devices have a separate address space from memory.

Example:

```text
IN  A, PORT1
OUT PORT2, A
```

#### Memory Mapped I/O

In memory mapped I/O, I/O device registers are treated like memory locations.

Example:

```text
LOAD R1, [5000]
STORE [5001], R1
```

#### Conclusion

I/O mapped I/O uses separate instructions and address space for I/O devices. Memory mapped I/O uses the same address space and same instructions as memory.

### Q5. Explain Daisy Chaining Priority Interrupt mechanism with diagram.

#### Answer

==Daisy chaining== is a hardware priority interrupt method in which devices are connected serially to determine interrupt priority.

The device closest to CPU has the highest priority.

#### Diagram

```text
CPU Interrupt Acknowledge
        |
        v
+----------+    +----------+    +----------+
| Device 1 |--->| Device 2 |--->| Device 3 |
+----------+    +----------+    +----------+
 Highest                         Lowest
 Priority                        Priority
```

#### Working

1. Multiple devices may send interrupt requests.
2. CPU sends interrupt acknowledge signal.
3. Signal passes through devices in sequence.
4. First requesting device captures the acknowledge signal.
5. That device places its interrupt vector on the bus.
6. Lower priority devices do not receive acknowledge until higher priority device passes it.

#### Advantages

- Simple hardware.
- Easy priority assignment.
- Less wiring required.

#### Disadvantages

- Priority is fixed.
- Failure of one device can affect lower devices.
- Lower priority devices may suffer starvation.

#### Conclusion

Daisy chaining is a simple priority interrupt technique where priority depends on the physical position of the device in the chain.

### Q6. Explain Peripheral Devices.

#### Answer

==Peripheral devices== are external devices connected to a computer system for input, output, or storage.

They help users communicate with the computer and store or retrieve information.

#### Types of Peripheral Devices

| Type | Examples |
|---|---|
| Input devices | Keyboard, mouse, scanner, microphone |
| Output devices | Monitor, printer, speaker, projector |
| Storage devices | Hard disk, SSD, pen drive, CD/DVD |
| Communication devices | Modem, network card, Wi-Fi adapter |

#### Input Devices

Input devices are used to enter data and instructions into the computer.

Example: keyboard, mouse, scanner.

#### Output Devices

Output devices display or produce processed results.

Example: monitor, printer, speaker.

#### Storage Devices

Storage devices store data permanently or temporarily.

Example: HDD, SSD, optical disk.

#### Communication Devices

Communication devices allow data transfer between computers.

Example: modem, network interface card.

#### Conclusion

Peripheral devices extend the functionality of a computer system by providing input, output, storage, and communication facilities.

### Q7. Explain Programmed I/O with example.

#### Answer

==Programmed I/O== is an I/O technique in which CPU directly controls the transfer of data between I/O device and memory.

CPU continuously checks the status of the device before transferring data. This is called polling.

#### Working

1. CPU sends command to I/O device.
2. CPU checks device status repeatedly.
3. When device is ready, CPU transfers data.
4. CPU continues this process until transfer is complete.

#### Example

```text
While device is not ready:
    keep checking status
Transfer data when ready
```

#### Advantages

- Simple to implement.
- No extra hardware required.

#### Disadvantages

- Wastes CPU time.
- CPU remains busy in polling.
- Not suitable for high-speed devices.

#### Conclusion

Programmed I/O is simple but inefficient because CPU must continuously monitor the I/O device.

### Q8. Explain structure of Magnetic Disk System and how to find its capacity.

#### Answer

A ==magnetic disk== is a secondary storage device that stores data on rotating magnetic platters.

#### Structure

```text
+--------------------------------+
| Disk platter                   |
|  Tracks: circular paths        |
|  Sectors: divisions of tracks  |
+--------------------------------+
        ^
        |
 Read/Write Head attached to arm
```

#### Important Terms

| Term | Meaning |
|---|---|
| Platter | Circular magnetic disk |
| Track | Circular path on disk surface |
| Sector | Small division of a track |
| Cylinder | Same track number on all platters |
| Read/write head | Reads or writes data |

#### Capacity Formula

```text
Disk capacity = Number of surfaces x Tracks per surface x Sectors per track x Bytes per sector
```

#### Example

If disk has:

```text
2 surfaces, 100 tracks/surface, 50 sectors/track, 512 bytes/sector
```

Then:

```text
Capacity = 2 x 100 x 50 x 512
Capacity = 5,120,000 bytes
```

#### Conclusion

Magnetic disk stores data on tracks and sectors. Its capacity depends on surfaces, tracks, sectors, and bytes per sector.
